ポイント管理Webアプリ

HTML CSS JavaScript LocalStorage

概要

子どものお小遣い管理をきっかけに制作したポイント管理Webアプリです。 ポイントを付与する条件や目標を設定し、達成状況を確認できる仕組みとして制作しました。 現在は、お小遣い管理に限らず、業務・学習・生活など、さまざまな場面で利用者に合わせた使い方ができるアプリとして継続開発しています。

制作背景

子どものお小遣いをポイント制で管理していましたが、ポイントの加算・減算や現在のポイント、目標までの進捗を管理することが煩雑になることが課題でした。 そこで、ポイントの増減や目標までの進捗をまとめて確認できる方法としてWebアプリを制作しました。 また、実際に使う中で、お小遣い管理だけでなく、業務や学習などさまざまな場面で活用できる仕組みにできるのではないかと考え、機能を拡張しています。

主な機能

  • ユーザー・項目の追加／編集／削除
  • ポイント加算・減算・支給
  • 個人目標・共有目標
  • 履歴表示・データ永続化
  • 累計ポイント・目標達成までの進捗表示

工夫した点

  • ポイントを付与する行動や条件を利用者に合わせて設定できる柔軟な設計
  • 進捗バーによって、目標達成までの状況を直感的に確認できる設計
  • お小遣い管理に限らず、業務・学習・生活など用途に応じて活用できる構成
  • Googleスプレッドシートなどの外部データに依存せず、アプリ内でデータを管理できる構成

改善の過程

  • 実際に使用する中で、お小遣い管理だけでなく、さまざまな用途で活用できる仕組みにしたいと考え、ポイントの付与条件や目標を柔軟に設定できるよう改善
  • ポイントを貯めるだけでなく、目標までの達成状況を確認できるよう、目標機能や進捗表示を追加
  • ポイントの増減を後から確認できるよう、履歴表示機能を追加

今後の改善

  • 管理者画面とユーザー画面を分け、用途に応じてそれぞれの操作範囲を設定できる権限管理機能を実装予定
  • お小遣い管理・業務・学習など、利用者や用途に応じて操作できる機能を自由に設定できる仕組みへ拡張予定
  • 最終的にはモバイルアプリとして再構築し、実際にリリースすることを目指す

Salesforce試験対策アプリ（GAS）

Google Apps Script JavaScript HTML/CSS Google Sheets

概要

Salesforce資格試験の学習効率向上を目的として制作したWebアプリです。 購入した問題集をより実践的に活用できるよう、ランダム出題や誤答問題の復習機能などを実装し、外出先やスキマ時間でも学習できる環境を構築しました。

制作背景

購入した問題集が長文形式だったため、スクロール中に答えが見えてしまうことや、外出先で学習しづらいことが課題でした。 また、数百問ある問題を繰り返し解く中で、同じ問題や回答順を覚えてしまうことで、本当に問題を理解できているのか判断しづらいと感じました。 そこで、実際の試験を意識して問題数を固定し、ランダムに出題できる学習環境を自分で作ることにしました。

主な機能

  • ランダム出題
  • 誤答問題のみの再出題
  • 正誤判定・解説表示
  • 正答率表示
  • 回答時間表示
  • 途中終了機能
  • Google Sheetsから問題データ取得

工夫した点

  • Google Sheets上で問題を管理できる構成
  • コードを変更せず問題を追加・更新できる設計
  • スマートフォンでも学習しやすいシンプルなUI
  • 実際の試験を意識した問題数固定と出題形式
  • スキマ時間でも学習できるよう、途中終了時にもその時点の正答率を確認できる設計

改善の過程

  • 最初は数百問の過去問を順番に解く形式で制作
  • 本番と同じように問題数を固定して出題できるよう変更
  • 同じ問題や回答順を覚えてしまうことから、ランダム出題を追加
  • 本番では正答率によって合否が決まるため、正答率表示を追加
  • 何度も間違える問題を重点的に復習できるよう、誤答問題のみを再出題する機能を追加
  • 問題を解くのにかかる時間を把握するため、回答時間の計測機能を追加
  • スキマ時間でも学習できるよう、途中終了機能を追加し、その時点での正答率を表示できるよう変更
  • 学習履歴の表示機能も検討したが、実装に時間がかかることと試験日が迫っていたことから、学習履歴はGoogle Sheetsで管理する方法に切り替え

制作後の変化

  • 問題集をそのまま解くのではなく、ランダム出題による反復学習ができるようになった
  • 誤答問題を繰り返し解くことで、苦手な問題を重点的に復習できるようになった
  • 正答率や回答時間を確認しながら、自分の学習状況を把握できるようになった
  • アプリを使って学習を継続し、Salesforce 認定アドミニストレーター試験に合格

Game Portfolio

HTML CSS JavaScript

概要

HTML・CSS・JavaScriptを用いて制作したゲーム風ポートフォリオです。 作品を掲載するだけでなく、自分らしい発想やUI/UXへの考え方も体験を通して伝えられるポートフォリオを目指し、キャラクターを操作して各コンテンツへ移動するゲームライクなUIを採用しました。

制作背景

一般的なポートフォリオとは異なる形で、自分らしさや発想力を表現したいと考え、ゲームの世界を探索するようにコンテンツを見てもらえるサイトを制作しました。 見るだけではなく、実際に操作して楽しみながら各コンテンツへ進んでもらうことで、作品や自分自身に興味を持ってもらえる体験を目指しました。

主な機能

  • RPG風ホーム画面
  • キャラクター移動（WASD・矢印キー・スマホ操作対応）
  • 建物クリック・入口Hit Areaによるページ遷移
  • スプライトアニメーション
  • フェードアニメーション
  • モーダルによる作品紹介
  • レスポンシブ対応

工夫した点

  • ゲームのように探索しながら各コンテンツへ進める導線を設計
  • 建物へのクリック・接触のどちらでも操作できるUIを設計
  • ゲームらしい操作感を意識したキャラクターや画面のインタラクションを実装
  • 各ページのデザインやUIを統一し、サイト全体でゲームの世界観を維持
  • 「操作する楽しさ」と「ポートフォリオとしての見やすさ」の両立を意識して設計

フィードバック・改善

  • 「インパクトがあってGood」「世界観がいい」「ドラクエを思い出しました、素敵です！」など、ゲーム風の表現や世界観について好評を得た
  • 操作できることが分かりにくいという意見を受け、操作方法を画面内で伝えられる構成に改善
  • FVだけでは「何をしている人、何を目指している人なのか」が分かりにくいという意見を受け、メッセージや肩書きを追加
  • 迷わずストレスなく見てもらえることを意識し、クリックできる対象範囲を建物から看板まで広げるなど操作性を改善
  • タブレットで操作した際に世界観や操作性の良さが伝わりやすいという意見を参考に、各デバイスでの見え方や操作性を確認

今後の改善

  • ゲーム風としての楽しさを残しながら、初めて訪れた人でも迷わず各コンテンツへ進める導線を継続的に改善

NovaWorks株式会社コーポレートサイト

HTML CSS JavaScript

概要

NovaWorks株式会社という架空のIT企業を想定し、デザインからHTML/CSSによるコーディングまで一貫して制作しているコーポレートサイトです。AI導入支援やRPAによる業務効率化、Webシステム開発、データ分析支援などのサービスを提供する企業を想定しています。主に法人顧客を対象とし、サービス紹介やケーススタディ、企業情報、採用情報、News、Contactなどを掲載する構成を予定しています。

制作背景

実在する企業サイトを想定し、企業のサービスや実績、企業としての考え方などを整理して伝えられる、一般的なコーポレートサイトとして制作しています。主な顧客を法人としながら、Webエンジニアやデザイナーの採用情報も掲載することで、サービスを検討する企業だけでなく、求職者にも必要な情報を届けられる構成を考えています。

現在の実装状況

  • Heroセクション（ファーストビュー）の実装
  • 企業名、キャッチコピー、サービス内容などをHeroセクションに配置
  • HTML/CSSによるコーディング

今後実装予定

  • AI導入支援、RPAなどの業務効率化、Webシステム開発、データ分析支援のサービス紹介
  • ケーススタディによる導入実績の紹介
  • ミッション、ビジョン、バリューなどを含む企業情報
  • Webエンジニア、デザイナーの採用情報
  • Newsによる企業の最新情報
  • Contactフォームによる問い合わせ受付

工夫した点

  • 法人顧客を主な対象とした、一般的なコーポレートサイトとして情報構成を設計
  • サービス、実績、企業情報、採用情報など、目的の異なる情報を整理して掲載する構成を検討
  • 企業としての考え方や価値観も伝えられるよう、ミッション・ビジョン・バリューを掲載する構成を設計
  • デザインを実際にコードで実装する中で、細かな余白や配置、要素の大きさなどを忠実に再現する難しさを実感
  • 保守性や可読性を意識したHTML/CSSの実装

Talk Navi

Google Apps Script JavaScript HTML/CSS Google Sheets LocalStorage

概要

稼働前の練習や実際の架電で、相手の反応に合ったトークと必要な情報を確認できる、分岐型のトーク支援Webアプリです。選択肢を押すと次のトークが表示され、会話の流れに沿って進められます。

制作背景

稼働開始前の研修やロープレを通じて、相手の反応に応じて確認するトークや関連資料が分散していることに気づきました。想定外の返答があった際にも、会話の流れを保ちながら必要な内容を確認できる方法があれば、練習や実際の対応に役立つのではないかと考えました。未経験のメンバーから稼働への不安の声も聞いていたため、以前制作したSalesforce試験対策アプリの仕組みを応用し、状況に応じたトークや情報をアプリ内で確認できる形を考えました。

主な機能

  • 選択肢に応じたトーク分岐
  • 左側メニューからのトーク選択
  • 前のトーク・次のトークへの移動
  • キーボードによる操作と操作対象の切り替え
  • サービス内容の確認
  • メモ機能
  • スケジュール確認
  • メールアドレス確認用のフォネティックコード変換
  • 架電件数・担当者接触数のカウントと保存
  • Googleスプレッドシートからのトークデータ取得

工夫した点

  • Salesforce試験対策アプリで使った選択肢表示の仕組みを応用
  • トークスクリプトをもとに、相手の反応に応じて進める分岐構造
  • 選択肢をボタンで表示し、次のトークを直感的に選べるUIを設計
  • トークIDで分岐先を管理し、トークの流れを整理
  • Google Sheetsでトークデータを管理し、コードを変更せず内容を更新できる構成に設計
  • ロープレで動作を確認し、不足していた接続や誤った分岐先を修正

利用者の声

  • 「使いやすかった」
  • 「いきなり担当者までつながってテンパりました。これがないと無理でした。」
  • 「ボタンを押して遷移するので、簡単に練習できます。」
  • 「かなり便利」

フィードバック

  • キーボードだけで操作したい
  • 戻るボタンを誤って押した際に確認を表示してほしい
  • サービス内容を簡単に確認したい
  • メニューから別のトークへ移動した後も、元のトークへ戻りたい
  • 競合比較表をサポートメニューから確認したい

改善

  • 選択肢やメニュー、サポート機能などをキーボードだけで操作できるように変更
  • マウスの戻るボタンを押した際に「Talk Naviを離れますか？」と確認を表示し、誤操作による離脱を防止
  • サービス内容をアプリ内のサポートメニューから確認できるように変更
  • メニューから移動した後も、移動前のトークへ戻れる履歴機能を追加
  • 架電件数・担当者接触数のカウント機能を追加
  • スケジュール確認・フォネティックコード機能を追加
  • 不足していたトークの接続や誤った分岐を修正

導入後の変化

  • トークの流れや必要な情報をアプリ内で確認でき、資料を探す手間を削減
  • アプリ内で必要な情報を確認しながら、実際の対応を進めやすくなった
  • 架電件数・担当者接触数のカウントをアプリ内で行えるようになり、手作業で数える負担を軽減
  • 利用者から、練習や実際の対応に役立ったという感想を得た

今後の改善

  • 競合比較表は作成済み。今後、サポートメニューから確認できる機能として実装予定。

LOST LAMBS

TEAM PROJECT IN PROGRESS

概要

学習仲間に声をかけて立ち上げた「合同会社迷える子羊」というWeb制作チームで、チーム紹介サイト「Lost Lambs」の制作に取り組んでいます。企画から制作、公開までをチームで進めることを目標とし、定期的なMTGを行いながら制作を進めています。

制作背景

個人制作だけでなく、複数人でひとつのWebサイトを制作する経験を積みたいと考え、自ら企画して学習仲間に声をかけ、チームを立ち上げました。「Lost Lambs -We may be lost, but we're not alone-（迷ってるかもしれない。でも、ひとりじゃない。）」をコンセプトに、学習中だからこそ互いに協力しながら制作を進めるチームを目指しています。

現在の取り組み

  • チーム「合同会社迷える子羊」の企画・立ち上げ
  • Webサイト「Lost Lambs」の企画・制作
  • 定期MTGの実施と制作進行
  • メンバーの募集・役割分担
  • ディレクター兼コーダーとして制作に参加
  • 年内のWebサイト公開を目標に制作を進行

工夫している点

  • MTG内容やタイムスケジュールを事前共有し、議論を進めやすい環境を整備
  • メンバーの「できること」と「やりたいこと」をもとに役割を決定
  • ロゴ案が多数集まったため、評価基準を設定して投票する方法を検討・決定
  • 重要事項はNotionで管理し、Slackと併用して情報を整理
  • 実際の進行で見つかった課題をもとに、チームの進め方を改善
